# Output contracts

## search-plan.json

Generated by `build_search_plan.py`. It preserves every upstream exact task and adds transparent multi-direction product-search tasks for six strategy categories. Every product task includes `strategy_category`, `query_origin`, `category_purpose`, `search_direction`, and `search_round`.

## image-references.json

Generated by `prepare_image_review.py`. It is a URL-reference manifest, not a download manifest:

```json
{
  "schema_version": "2.0",
  "mode": "remote_url_reference",
  "records": [
    {
      "opportunity_id": "exact opportunity ID",
      "product_id": "exact evidence product ID",
      "image_url": "exact CLI-returned HTTPS image URL",
      "url_allowed": true,
      "error": ""
    }
  ],
  "allowed_count": 1,
  "rejected_count": 0,
  "downloaded_file_count": 0
}
```

Rules:

- every evidence product appears exactly once;
- `image_url` equals the product URL already present in `evidence.json`;
- only HTTPS URLs on the configured Alibaba image-host allowlist may set `url_allowed: true`;
- records contain no `relative_path`, `local_path`, `file_path`, cached bytes, or downloaded filename;
- the workflow creates no product-image directory and `downloaded_file_count` remains `0`.

- do not invent product IDs, company URLs, prices, visual facts, or claims.

## Recall funnel

`prepare_evidence.py` records these deterministic coverage fields for every opportunity:

- `raw_product_rows`: total product rows returned across product-search tasks;
- `product_count`: unique products after `product_id` deduplication;
- `duplicate_product_rows`: `raw_product_rows - product_count`;
- `retrieval_by_category`: task count and raw rows for every strategy category.

The HTML combines those fields with the exhaustive Agent decisions to show raw rows, deduplicated products, excluded products, observed products, and shortlisted products. The three decision counts must sum to `product_count`.
